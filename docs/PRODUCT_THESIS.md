# StratOS 产品命题研讨纪要

**日期：** 2026-07-14
**性质：** 产品定位与优先级共识（非需求规格，供 Blueprint / PRD 引用）
**状态：** 已达成共识，待择机纳入 [STRATOS_BLUEPRINT.md](./STRATOS_BLUEPRINT.md)

---

## 〇、一句话结论（最重要的产出）

> **StratOS 不是战略「规划」工具，是战略「坚守」工具。**
> 它的两个心跳：**事件风险**（平时静默、破线即硬阻断）+ **执行坚守**（让钱、承诺、意图的每一次偏离都留痕、无法粉饰）。

此定位比原有「战略沙盘 / 推演系统」**更锋利、更收敛**，建议作为核心命题。

---

## 一、用户定位：老板 vs 部门

- **现状（代码印证）：** 以老板为中心。最丰富的战略面锁在 **L3 CEO/CFO**（`lib/auth/permissions.ts`）；高管层（L2 vp/system_head）只有只读切片。
- **老板层做减法：** 砍认知负荷、留结论。老板只需回答两问——「**这月有没有破线？**」「**说好要坚守的，有没有在松掉？**」
- **高管/部门层做加法：** 从「只读切片」升级为「有我的责任、能写回、有提醒」——但**必须事件驱动，不能变成月度打卡**。

---

## 二、节律：三层解耦

| 频率类型 | 合理节奏 | 机制 |
|----------|----------|------|
| 战略制定 / 修订 | 半年 / 一年 | H1、FY 快照 |
| 战略复盘 / 纠偏 | 季度 | 季报 QTR-REV |
| 事件监控 / 预警 | **事件驱动**（平时静默） | `HealthAssertion` 破线才尖叫 |

**月度作为「战略节奏」太频繁且违背自身边界；作为「记账 / 留痕」则有价值。**

---

## 三、理论套路：分层，不删（已修正）

> 早前表述「老板屏上每个理论名词旁必须有人话，否则删掉」**过头，已收回**。

- **理论作为「决策纪律」——必须保留。** 框架（Rumelt / Mintzberg / Cynefin / BSC / Doctrine / 五事七计）的价值正是**对抗拍脑袋**。要科学管理，就越需要这套纪律压制直觉偏误。一个都不能少。
- **理论作为「界面词汇」——可下沉，非隐藏。** 问题不是「理论该不该在」，而是「要不要一上来就用黑话砸人」。

**原则（替换旧「铁律」）：**

> **结论用人话，依据可追溯。**
> 老板屏先给**决策级结论**；每个结论旁一键可下钻到**背后的框架推演**——这才是「科学决策」，而非「换个说法的拍脑袋」。

**示例（同一件事）：**
- 纯黑话 ❌：「Rumelt 诊断：crux = 热泵产品化；Cynefin 域 = complex」
- 纯人话（矫枉过正）❌：只说「产品化是今年瓶颈」——无依据，老板凭什么信
- 分层 ✅：标题「**今年只打一场硬仗：热泵产品化（12 个月窗口）**」 → 一键展开「**为什么是它**：Rumelt 三步 + 数据支撑」，旁标「complex 域，按试点信号而非年度 KPI 考核」

**降的是默认视图的认知负荷，不是决策深度与科学性。**

---

## 四、月报的角色：留痕，不是决策触发器

- 月报入库 = **防篡改史料**，喂养 `StrategicSnapshot`（只读）+ `audit_hash_chain`（防篡改）+ `StrategyPattern`（Mintzberg 战略形成史）。
- 是「记账频率」，不是「开会频率」——**记账可勤，不逼人每月开会**。

---

## 五、落地共识：高管「坚守驾驶舱」

- **应该做**，核心模块是**承诺兑现**。
- 关键发现：`Commitment` 模型已含 `userId / deadline / status / completionNote`——**零迁移即可实现**。
- 设计要点：
  - 承诺三态：逾期（红置顶）/ 临期（≤7 天黄）/ 在途；按人聚合「我的承诺 + 我团队欠的」。
  - **一键兑现**写回：仅限承诺、到期才需动，非月度表。
  - 提醒**只做应用内**（登录置顶 + 侧栏角标），守住「无实时 API」边界。
  - 引入 `HealthAssertion` overlay——**风险 + 坚守同屏**。
  - 季度生成兑现率，进快照 / diff 留痕。
- 切片隔离复用既有 `assertSliceAccess` / slice 过滤。

**节奏：** P0 纯读 `/cockpit`（承诺三态 + 切片隔离，不碰 DB）→ P1 提醒 + 断言 overlay → P2 季度兑现率留痕。

## 六、由命题推出的产品纪律（取舍标准）

- **强化：** 断言触达、`budget_tag ↔ FPA` 勾连完整度、承诺追踪、diff 里「偏离」高亮。
- **克制：** 一切「每月填一版规划」「全员打卡」「再加一个理论模块」的冲动——那是运营工具，不是坚守工具。

## 七、战略脊梁：价值观 / BSC / OKR-TTI / 承诺（核心关系）

> 承诺管理不是新轮子，是 OKR 的「个人最后一公里」。以下关系经研讨确认，且大部分已在 schema 中就位。

### 7.1 分层（自上而下）

```
价值观层（软，不硬关联）：四个满意 + Doctrine —— 精神朝向，仅理念对齐，非数据外键
        ⇕ orientation（非 FK）
BSC 底线 = 年度预算 × 各体系板块 × 经营结果底线要求（硬 · must-not-fail · 四灯）
        ↑ 先导驱动
OKR-TTI（Target to Improve · 先导指标推进 · targetValue → currentValue · confidence）
        ↑ 最后一公里
承诺 Commitment ──【待补】linkedKrId

BSC 底线红灯 ──有力度──→ 考核（绩效） + 任用（五事「将」）
```

### 7.2 各层定位（含代码对应）

| 层 | 定位 | 代码字段 / 位置 |
|----|------|-----------------|
| **四个满意** | **价值观 / Normative**，精神朝向，**不硬关联** | `/culture` · Doctrine 审计（不打分） |
| **BSC KPI** | **年度预算各体系板块的经营结果底线**（must-not-fail） | `PlanObjective.dimension / mustNotFail / mustWinStatus(TrafficLight)` |
| **OKR-TTI** | **先导指标**，衡量 OKR 推进进展、能否撑起未来基础 | `KeyResult.targetValue / currentValue / confidence / isLeadingIndicator`；`ExecutionScoreboardConfig.leadingKrIds` |
| **承诺** | 个人级、有截止日、点对点的**兑现原子** | `Commitment`（缺 `linkedKrId`） |

### 7.3 坚守闭环（补上 linkedKrId 后）

```
承诺逾期 → 拖累 linkedKr 的 TTI（currentValue 停滞）
        → KR 先导指标示警（confidence↓）
        → 威胁 Objective → BSC 底线四灯变色
        → 危及对应「体系板块」的经营结果底线
```

### 7.4 红灯的「牙齿」：A + B（不打分）

> 定档 **A + B**；明确**不做 C（打分联动）**，与「Gate 清单 > 假分数」立场一致。

- **A · 展示：** BSC 底线红灯旁标注「应进考核 / 影响任用」，由人判断。（零 schema）
- **B · 留痕：** 红灯自动生成一条**问责记录**，挂责任人 + `/culture` 五事「将」（关键岗位胜任度）。（小 schema）
- **C · 打分联动：** ❌ 不做——不自动改绩效分 / 胜任度分数。
