# StratOS · 更高维产品设计框架

**版本：** v1.1 · 2026-06-14  
**状态：** Meta 层 I1–I5 **已批准导入**（见 [THEORY_IMPORTS.md](./THEORY_IMPORTS.md)）；I6–I8 Phase 2。  
吸收当代战略管理知识体系，定义 **第二阶（Meta）产品层** —— 让 StratOS 从「战略仪表盘」进化为 **「战略认知与学习系统」**。

## 一、我们现在的「维度」在哪里

| 维度 | 名称 | StratOS 现状 | 同类软件 |
|------|------|--------------|----------|
| **D1** | 计划对齐 | BSC + OKR + Vx | Cascade、Profit.co |
| **D2** | 执行监控 | 看板 + 月报 + 预警 | WorkBoard |
| **D2.5** | 财务验证 | FPA B-A-F | Anaplan（更重 FP&A） |
| **D2.5** | 版本史学 | 两次快照 + diff + Robust | **几乎无对标** |

**结论：** 我们已在 D2–D2.5 有差异化（快照史学 + 稳健性 + 价值观底线）。  
**缺口：** 尚未进入 **D3 战略认知层** —— 回答的不是「目标多少」，而是：

- **为什么打这场仗？**（诊断）
- **在什么情境下用什么方法？**（辨识）
- **计划与涌现之间学到了什么？**（学习）
- **系统里哪里在起反作用？**（系统）

## 三、Rumelt 内核 × 现有架构（关键升维）

Rumelt：**坏战略** = 只有目标；**好战略** = 内核三件套。

```
┌─────────────────────────────────────────────────────────┐
│  1. Diagnosis 诊断                                       │
│     「真正的核心挑战是什么？」— 瓶颈、矛盾、根因           │
├─────────────────────────────────────────────────────────┤
│  2. Guiding Policy 指导方针                              │
│     「用什么打法克服？」— 不是目标，是约束与方向           │
│     ↔ StratOS：三支柱 Doctrine + BLM 业务设计            │
├─────────────────────────────────────────────────────────┤
│  3. Coherent Actions 连贯行动                            │
│     「哪些行动彼此强化而非互斥？」                         │
│     ↔ StratOS：OKR + Vx + 预算 + FPA 一致性审计          │
└─────────────────────────────────────────────────────────┘
```

**产品缺口：** 我们有 Guiding Policy（Doctrine）和 Coherent Actions（OKR/Vx），但 **缺少显式的 Diagnosis 对象**。

**升维设计 · 新增 `StrategicDiagnosis`：**

| 字段 | 说明 | 示例（瑞合） |
|------|------|--------------|
| `challenge_statement` | 一句话核心挑战 | 「从 1 亿到 2.5 亿，渠道与产品能力不同步」 |
| `bottleneck` | 战略瓶颈类型 | 能力 / 市场 / 组织 / 资本 |
| `root_causes` | 3–5 条根因 | 单王不足、V4 延迟、酒店渠道集中度过高 |
| `crux` | Rumelt「枢纽」— 最小杠杆点 | 「热泵产品化能力能否 12 个月内成立」 |
| `linked_assumptions` | 诊断依赖的 Hx | H1, H3 |
| `valid_until` | 诊断有效期 | 2026-FY 快照前需重检 |

**UI：** 看战略页 **最上方** 不是使命愿景，而是 **「今年我们认定的核心挑战」** — 30 字以内。

## 五、Mintzberg： deliberate / emergent — 快照史学的理论升华

**高维洞察：** 你们「两次战略会版本对比」的本质，不仅是 diff KPI，而是 diff **战略形成模式**。

| 类型 | 定义 | 在 StratOS 中如何识别 |
|------|------|------------------------|
| **Deliberate 刻意** | 年初/初定的 OKR、Vx、Budget | 写入 FY 快照的意图字段 |
| **Emergent 涌现** | 执行中出现的模式，未在年初计划 | 月报/季报累积后 **模式识别** |
| **Unrealized 未实现** | 计划了但没发生 | diff：计划有、实际无 |
| **Serendipitous 偶成** | 没计划但做成了 | diff：实际有、计划无 → **学习金矿** |

**升维产品 · `StrategyPattern` 对象：**

```
每版快照自动生成：
├─ deliberate_realization_rate   刻意战略实现率
├─ emergent_pattern_list       涌现模式清单（如「恒热区县经销商自发增长」）
├─ unrealized_list             未实现意图
└─ learning_prompt             「涌现是否应写入下版 deliberate？」
```

**这是 StratOS 比 Cascade/WorkBoard 高维的核心：** 它们追踪 **目标**；我们追踪 **战略是如何形成的**。

## 六、动态能力：Sense · Seize · Transform（产品化三环）

Teece 三环不应只在 StratReview 文字里，应成为 **模块间标准流程**：

```
Sense 感知          Seize 捕捉           Transform 重构
─────────          ─────────           ────────────
StratForesight  →  StratCraft/Decode  →  StratPilot/Finance
竞品/政策/雷达      假设→OKR→Vx定稿       资源重配·组织调整
     ↑                    ↑                      ↑
     └──────────── StratReview 复盘：哪一环断了？ ────┘
```

**升维 · 健康度增加「DC 三环」视图：**

| 环 | 诊断问句 | 信号 |
|----|----------|------|
| Sense | 我们是否早看到变化？ | 假设失效前有无预警记录 |
| Seize | 看到后是否果断调整？ | 事件→OKR 修订的延迟天数 |
| Transform | 是否真正升级能力？ | 同类问题是否重复出现 |

## 七、Cynefin：为决策选方法（不是一刀切）

**问题：** 用 OKR 管一切、用 BSC 管一切，在 **复杂域** 会失败。

| 域 | 特征 | 战略决策法 | StratOS 应怎么做 |
|----|------|------------|------------------|
| **Clear 清晰** | 最佳实践已知 | 标准化 | KPI 监控、SOP |
| **Complicated 繁杂** | 专家可分析 | 分析→决策 | BLM、FPA 敏感性 |
| **Complex 复杂** | 因果事后才清晰 | **探测→感知→响应** | 假设验证、Vx 试点、安全失败 |
| **Chaotic 混沌** | 需先稳定 | **行动→感知** | 事件快会、CEO 裁决 |

**升维设计：**

- 每个 **假设 Hx**、**Vx 项目**、**战略议题** 打 `cynefin_domain` 标签  
- UI 显示 **推荐方法论**（如 Complex → 不要强行定年度 KPI，用季度探测）  
- AI 顾问回答时 **先判域再给建议**

## 八、系统思维：从因果链到反馈环

StratDecode 现有「因果链」是 **线性**（学习→流程→客户→财务）。

**升维 · 增加反馈环类型（轻量，非系统动力学全建模）：**

| 环类型 | 示例 | 产品 |
|--------|------|------|
| **增强环 R** | 签约↑→口碑↑→签约↑ | 标注 R，提示「勿过度乐观」 |
| **调节环 B** | 降价↑→份额↑→利润↓→投入↓ | 标注 B，FPA 联动 |
| **延迟 D** | 培训→6月后→中标率 | 标注延迟，OKR 不误判 |

MVP 可在 BSC 地图上用 **R/B/D 图标** 标注关键链，完整版做 StratSim 系统动力学。

## 十、Kotter 双系统：StratOS 的「元定位」

对外叙事升维：

```
层级操作系统（ERP/OA/CRM）     →  跑今天的业务
战略网络操作系统（StratOS）     →  设计明天的仗
         ↑                                    ↑
         └──────── 数据导出 / 决议回灌 ────────┘
```

StratOS **不负责日常运营**，负责 **30 人战略网络的节律、语言、快照、学习** — 这与 Kotter「第二操作系统」同构。

## 十三、与四个满意 / 三支柱 / FPA 的融合（不冲突）

| 已有 | 高维增强 |
