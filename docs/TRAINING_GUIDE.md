# StratOS · 培训与上线指导手册

**版本：** v1.0 · 2026-06-23  
**适用对象：** CEO / CFO / VP / 战略部 / 系统管理员  
**用途：** 内部培训、上线交接、日常操作参考

---

## 一、软件是什么 · 解决什么问题

### 一句话定位

> **StratOS 是一套面向战略会的作战指挥系统**：把战略诊断、资源配置、执行监控、风险阻断四条防线整合进同一个平台，让每次战略决策有数据依据、有历史对比、有硬性风险阻断。

### 没有它之前的痛点

| 痛点 | 典型场景 |
|------|----------|
| 战略会靠 PPT，数据不联动 | 财务数字和项目进展分两个文件，对不上 |
| 重大决策无法追溯 | 半年前批了哪个投资项目、当时的假设是什么？不知道 |
| 执行偏差靠感觉发现 | 项目延期、假设失效，要等人主动汇报才知道 |
| 风险触发无硬性机制 | 现金 runway 已低于 3 个月，但系统里没有任何阻断 |
| 竞争态势和内部战略割裂 | 竞品分析在另一个文件，和投资决策不联动 |

### 有了它之后

- **战略会前**：一键拉取诊断 + FPA + OKR + 项目进展 + 风险清单，10 分钟完成会前准备
- **战略会中**：`/command` 指挥甲板驱动议程，决策实时入库
- **战略会后**：快照冻结，历史可追溯，下次战略会自动对比偏差
- **月度例行**：导入月报/季报，系统自动触发健康断言、更新执行记分板

## 三、核心概念速查（必看）

### 3.1 数据来源信号灯

页面顶部会出现一条数据来源横幅：

| 颜色 | 含义 | 该怎么做 |
|------|------|----------|
| 🟢 绿色 · 数据库 | 数据来自真实 DB，近期有更新 | 正常使用 |
| 🟡 黄色 · 数据较旧 | 某核心表（如 FPA/项目）超过 7 天未更新 | 通知责任人更新 |
| 🔴 红色 · 演示数据模式 | 数据库不可用，显示示例数据 | **禁止用于真实决策** |

> **关键规则：战略会前必须确认横幅为绿色。**

### 3.2 四类健康断言（硬阻断）

系统在以下四种情况会触发**一票否决硬阻断**，阻止战略快照冻结：

| 断言类型 | 触发条件 | 解除方式 |
|----------|----------|----------|
| `runway` 现金告急 | 现金 runway < 3 个月 | 更新 FPA 使 runway 恢复 |
| `compliance` 合规事故 | 月报/季报含"重大""合规""事故"关键词 | CEO 手动例外批准并留注 |
| `talent` 人才流失 | 核心团队流失 > 30% | 更新月报数据 |
| `brand` 品牌危机 | NPS < 0 | 更新 FPA/运营指标 |

> CEO 可在 `/health` 页面对活跃断言添加例外批注，但必须留痕。

### 3.3 战略快照与版本

```
WorkingVersion（可编辑草稿）
        ↓ 战略会批准
StrategicSnapshot（冻结，不可改）
        ↓ 自动对比
DiffRecord（变更清单）+ StrategyPattern（Mintzberg 战略形成分析）
```

- **快照一旦冻结不可修改**，这是系统的核心审计机制
- 每次战略会结束后，由系统管理员执行冻结操作

### 3.4 三栈与 FPA 勾连

每个重大投资必须挂载 `budget_tag`（预算标签），系统据此自动关联到 FPA 预测行：

- **InvestmentCase（IC）**：战略投资项目
- **ProductBet**：产品押注
- **GtmBet**：市场/渠道押注

Bet 状态变更（批准/拒绝/暂缓）会自动开关对应 FPA 预测曲线。

## 四、各角色操作 SOP

### 4.1 CEO · 战略会主持人

**战略会前（提前 1 天）**

1. 打开 `/rehearsal` → 查看彩排摘要（诊断核心、现金 runway、健康断言）
2. 确认页面顶部数据源横幅为 **绿色**
3. 若有 🔴 红色健康断言 → 通知 CFO/战略部处理，或在 `/health` 添加例外批注
4. 打开 `/compass` → 确认北极星目标与里程碑进度是否需要更新

**战略会中**

1. 打开 `/command` 指挥甲板，以此驱动全部议程
2. 重大决策现场录入 → 由战略部负责人操作 `/strategy` 或 `/finance` 更新
3. 会后由系统管理员执行快照冻结

**月度例行（每月 5 日前）**

1. 确认当月月报已上传并解析（`/reports`）
2. 查看 `/health` 确认断言状态
3. 查看 `/inbox` 处置待办信号

---

### 4.2 CFO · 财务负责人

**月度更新（每月 3 日前）**

1. 打开 `/finance` → FPA 数字更新（收入/利润/现金）
2. 若有 Sheet 财务数据 → 在 `/reports` 上传 Excel，系统自动解析
3. 检查 CapStack（资本配置）是否与已批准 IC 一致
4. 检查 SPBP 情景概率是否需要根据最新信号调整

**战略会前**

1. 打开 `/finance` → 导出五年展望给与会者
2. 确认 M&A 管道（`/finance` → M&A 管道标签页）阶段是否需要更新
3. 确认现金 runway 断言状态 → 若触发，提前与 CEO 沟通例外处理

---

### 4.3 VP / 项目负责人 · 执行层

**每周更新（周五前）**

1. 打开 `/execution` → OKR 记分板 → 更新关键结果当前值
2. 找到自己负责的项目（Vx） → 更新里程碑进度、风险等级
3. 若假设已失效 → 在 `/execution` → 假设库中将结果标为 `failed`，并填写影响说明
4. 查看承诺库 → 确认本周承诺是否已完成

**战略会前**

1. 打开 `/execution` → 矛盾分析页，确认自己负责项目的矛盾项是否已有缓解措施
2. 查看 `/gates` → Gate 清单页，确认自己项目的 Gate 项状态是否最新

---

### 4.4 战略部 · 系统主理人

**日常维护**

1. **每月导入报告**：`/reports` → 上传月报/季报 PDF 或文本 → 点击解析 → 检查解析结果
2. **数据源巡检**：每周一确认 `/command` 数据源横幅为绿色
3. **战略解码更新**：每季度更新 `/decode` → BSC 战略地图 + Hoshin X 矩阵
4. **竞品追踪**：每月更新 `/market` → 竞品轨迹 + Hermes 信号

**战略会前（提前 3 天）**

1. 打开 `/versions` → 确认当前 WorkingVersion 内容完整
2. 打开 `/strategy` → 确认三栈 Bet 状态、诊断版本为最新
3. 检查 `/gates` → 五力分析 + Gate 清单是否已填写本期内容
4. 在 `/culture` → 五事就绪度页面，更新道/将/法三项内部评估
5. 运行 `/rehearsal` → 确认彩排摘要无异常

**战略会后（次日）**

1. 进入 `/admin` → 版本管理 → 冻结当前 WorkingVersion 为 StrategicSnapshot
2. 检查 DiffRecord 是否生成，确认变更清单完整
3. 在 `/versions` 查看 Mintzberg 战略形成分析（deliberate vs emergent 比例）

---

### 4.5 系统管理员 · 技术运维

**上线前（见第五节）**

**日常巡检**

1. 每天检查服务日志中是否有 `DATABASE_URL` 连接失败
2. 确认 `/api/data-source` 返回 `signal: "green"`
3. 定期执行 `prisma migrate deploy` 确保 schema 最新

## 五、上线指导手册

### 5.1 环境要求

| 项目 | 要求 |
|------|------|
| Node.js | ≥ 20 |
| PostgreSQL | ≥ 15 |
| 内存 | ≥ 2GB（推荐 4GB） |
| 外部依赖 | WorkOS（认证）、OpenAI/兼容 LLM API（可选）、字体服务 |

### 5.2 环境变量清单（必填）

```bash
# 数据库
DATABASE_URL="postgresql://user:password@host:5432/stratos"

# 认证（WorkOS）
WORKOS_API_KEY="..."
WORKOS_CLIENT_ID="..."
NEXTAUTH_SECRET="..."
NEXTAUTH_URL="https://your-domain.com"

# 可选：LLM（不填则退回规则引擎）
OPENAI_API_KEY="..."          # 或兼容 API
OPENAI_BASE_URL="..."         # 自定义端点时填写

# 生产环境安全开关（必须设置）
NODE_ENV="production"
# 禁止 demo fallback（生产必须设为空或不设）
# STRATOS_ALLOW_DEMO_FALLBACK=1  ← 仅紧急降级时启用
```

> `.env.example` 文件包含所有变量模板，参考填写。

### 5.3 首次部署步骤

```bash
# 1. 安装依赖
npm install

# 2. 同步数据库 schema（首次）
npx prisma migrate deploy
# 或开发环境：
npx prisma db push

# 3. 生成 Prisma Client
npx prisma generate

# 4. 构建
npm run build

# 5. 启动
npm start
# 或使用 Docker：
docker-compose -f docker-compose.prod.yml up -d
```

### 5.4 首次上线数据初始化顺序

按以下顺序录入，避免外键依赖报错：

```
① /admin → 系统设置 → 设置当前战略期间（如 2026-FY）
② /admin → 组织架构 → 创建 OrgUnit 树
③ /admin → 用户管理 → 创建用户并分配角色
④ /strategy → 战略诊断 → 录入第一版诊断
⑤ /strategy → 投资组合 → 录入 InvestmentCase
⑥ /finance → FPA → 录入当期收支数字
⑦ /execution → 目标与 KR → 录入 OKR
⑧ /execution → 项目 → 录入进行中 Vx 项目
⑨ /gates → 五力 + Gate 清单 → 填写本期评估
⑩ /versions → 冻结第一个基线快照
```

### 5.5 角色权限说明

| 角色 | 权限级别 | 可操作范围 |
|------|----------|-----------|
| `ceo` | Level 3（最高） | 全部读写 + 例外批准 |
| `cfo` | Level 3 | 全部读写 |
| `vp` | Level 2 | 读全部 + 写自己负责模块 |
| `system_head` | Level 3 | 全部读写 + 管理员功能 |
| `pm` | Level 2 | 读全部 + 写项目/假设/承诺 |
| `staff` | Level 1 | 只读 |
| `observer` | Level 1 | 只读（战略会旁听） |

### 5.6 生产环境安全核查清单

上线前逐项打勾：

- [ ] `DATABASE_URL` 指向生产库，非测试库
- [ ] `NODE_ENV=production` 已设置
- [ ] `STRATOS_ALLOW_DEMO_FALLBACK` 未设置（或 ≠ 1）
- [ ] WorkOS 生产密钥已配置（非演示模式）
- [ ] `NEXTAUTH_SECRET` 已生成强随机字符串
- [ ] 访问 `/api/data-source` 返回 `{ "source": "database", "signal": "green" }`
- [ ] 访问 `/command` 页面顶部无红色演示数据横幅
- [ ] 以 `staff` 角色登录，确认无法访问管理员 API

## 六、常见问题 Q&A

**Q：页面显示"演示数据模式"红色横幅怎么办？**  
A：说明数据库连接失败。检查 `DATABASE_URL` 是否正确，数据库服务是否运行，网络是否可达。

**Q：导入 Excel 后数据没变化？**  
A：检查 `/reports` 解析结果页，查看解析引擎是否返回错误。Excel 需符合标准模板格式（见 `docs/REPORT_FORMATS.md`）。

**Q：健康断言一直显示无法解除？**  
A：断言由系统自动触发，需要实际数据改变才能解除。例如 runway 断言需要更新 FPA 使现金 runway > 3 个月。CEO 可在 `/health` 添加临时例外批注。

**Q：战略快照冻结失败？**  
A：检查是否有活跃的 HealthAssertion（硬阻断）。在 `/health` 处理断言后再尝试冻结，或 CEO 添加例外批注后方可冻结。

**Q：LLM 解析报告不准？**  
A：系统自动降级为规则引擎兜底。检查 `OPENAI_API_KEY` 是否配置。规则引擎可识别标准格式报告，非标格式建议先整理成标准模板再导入。

**Q：`/command` 页面加载很慢？**  
A：指挥甲板聚合 15+ 个数据源。首次加载正常，若持续慢超过 10 秒，检查数据库查询性能，考虑为核心表添加索引。
